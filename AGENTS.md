## Project Overview

**RacingCoach** is a business automation consulting website specializing in process automation and integration services.

**Tech Stack:**
- Frontend: Next.js 16.2.6 (App Router), React 19.2.4, TypeScript 5, Tailwind CSS 4
- Backend: Node.js API routes, Python automation scripts
- Integrations: Clockify (time tracking), Resend (email)
- Styling: Tailwind CSS 4 with custom color palette (`powder-*`, `dark-blue`)

## Quick Start

```bash
npm run dev          # Development server on http://localhost:3000
npm run build        # Production build
npm start            # Start production server
npm run lint         # Run ESLint
```

**Environment Variables** (`.env.local`):
- `CLOCKIFY_API_KEY` - Clockify workspace API key (used by `clockify_entry.py`)
- `RESEND_API_KEY` - Resend email service API key
- `RESEND_FROM_EMAIL` - Sender for password reset emails, on a domain verified in Resend (e.g. `Clarivex <no-reply@clarivex.app>`). Defaults to `onboarding@resend.dev`, which only delivers to the Resend account owner
- `SITE_URL` - Public site URL used in password reset links (e.g. `https://clarivex.app`). Set in production; locally it falls back to the request's host
- `OPENAI_API_KEY` - OpenAI API key (Racing page: Debrief Coach, lap summaries, Race Trends, Racecar Analysis RAG)
- `ANTHROPIC_API_KEY` - Anthropic API key, for AI features set to a Claude model in the Admin page's AI Model Control (`chatModel` in `src/lib/aiModels.ts` makes a `ChatAnthropic` for `claude-*` models: no temperature, as current Claude models refuse one, and low effort; LangChain's profile for them is told they support JSON-schema output, as `createAgent`'s fallback forces a tool call, which they refuse). The In-Car AI Coach's features offer OpenAI and DeepSeek models only (`aiModelsFor` in `src/lib/aiModelList.ts`), and claude-haiku-5-5 isn't offered: given tools and a response format together, it often answers without calling the tools
- `GOOGLE_TTS_API_KEY` - Google Cloud API key for Cloud Text-to-Speech (the Text-to-Speech API enabled on the project, the key restricted to it), the In-Car AI Coach's voice: Chirp 3 HD voices, spoken natively in en-US, pt-BR, de-DE, es-US or es-ES (`src/lib/coachVoice.ts`). Not the same thing as `GOOGLE_CLIENT_ID`. Unset, speech falls back to OpenAI `gpt-4o-mini-tts` (cedar)
- `ELEVENLABS_API_KEY` (or `ELEVEN_LABS_API_KEY`), `ELEVENLABS_<LANGUAGE>_<ROLE>_VOICE_ID`, `ELEVENLABS_MODEL_ID` - ElevenLabs text to speech (`src/lib/elevenLabs.ts`): the key, the Voice IDs of the voices set up in the ElevenLabs account, one per language (`ENGLISH`, `PORTUGUESE`, `GERMAN`, `LATINO` for Latin American Spanish, `ESPANA` for Spain's Spanish, by the Spanish accent) and role (`RACECOACH`, `ANNOUNCER_LEAD`, `ANNOUNCER_COLOR`), e.g. `ELEVENLABS_ENGLISH_RACECOACH_VOICE_ID`, fifteen in all, and optionally the model (default `eleven_multilingual_v2`). ### API Route Patterns
- Validate input early (required fields, email format)
- Check environment variables before making external calls
- Return `NextResponse.json()` with appropriate status codes
- Handle errors gracefully with clear error messages
- AI coaches never say where on the track something happens (a distance from the start/finish line or a share of the lap): give the model only distances relative to a reference (e.g. "15 ft after your fastest run's brakepoint"), put `brakeChangeRule` (`src/lib/debriefCoach.ts`) in its prompt when its data has brakepoints, else `TRACK_POSITION_RULE`, and pass its answer through `src/lib/trackPositions.ts` (`withoutTrackPositions`: one rewrite, then the sentences that still do are dropped). `npm run test:track-positions` tests the check

**Example API route structure:**
```typescript
export async function POST(request: Request) {
  try {
    const body = await request.json();
    // Validate
    if (!body.requiredField) {
      return NextResponse.json({ error: 'Missing field' }, { status: 400 });
    }
    // Process
    // Return
    return NextResponse.json({ success: true });
  } catch (error) {
    return NextResponse.json({ error: 'Internal error' }, { status: 500 });
  }
}
```

## Lap Telemetry Retention

Uploaded laps (`"CollectorLaps"`) and saved Debrief Coach runs (`"DebriefSessions"`) are kept 30 days for Bronze, 60 for Silver and 90 for Gold, never more than 90, counted from each lap's completion (`completed_at`, the collector's `recordedAt` but never later than the upload) or the run's `created_at`. Disclosed in the Privacy Policy's Lap Telemetry Retention and Deletion section (`/privacy#lap-telemetry-retention`) and the Terms; operations, deployment and rollback in `docs/lap-retention.md`.

- **Rules**: `src/lib/lapRetentionRules.ts` (pure; an unknown level gets 30 days). The database applies the same rules in SQL (`src/lib/lapRetentionDb.ts`, run by `ensureUserSchema`): each row's `expires_at` is set when it's saved, and the `users_membership_lap_retention` trigger re-stamps the owner's unexpired rows whenever `"Users".membership_level` changes, by any route (Stripe, the Admin page, a paid period ending): up gives the longer period, down the shorter, so older laps expire at once, and a Gold membership that ends (Canceled, or Expired after a failed renewal) keeps them until 7 days after its paid period (`GOLD_GRACE_DAYS`, the grace period). Expired rows are never re-stamped, so nothing comes back. Change the rules, the SQL and the Privacy Policy together
- **Reads**: every lap and Debrief Coach read filters `expires_at > now()` (`visibleTo` in `src/lib/collectorLaps.ts`, `bot/db.js`), so an expired lap is gone everywhere, AI coaching included, before it's deleted. A new read of either table must filter it too
- **Uploads**: `saveCollectorLap` refuses a lap already past its period at the user's level, or one the cleanup deleted (a tombstone in `"ExpiredLaps"`), with `LapExpiredError`; `POST /api/collector/laps` answers 422 `{ code: 'lapExpired' }` (422 so collectors before 1.51.0 stop retrying it), and the collector deletes its local copy. A duplicate upload never changes `completed_at` or `expires_at`
- **Cleanup**: `src/instrumentation.ts` starts `src/lib/lapRetention.ts` in the web server: a minute after start, then hourly, `runLapRetentionJob` (one run at a time, by advisory lock) ends lapsed memberships for every account (`END_LAPSED_MEMBERSHIPS_SQL`, also run by `getUserById`), clamps any row past 90 days, then deletes expired laps (leaving tombstones, purged after 90 days) and debriefs in batches of 100, each its own statement. A dry run unless `LAP_RETENTION_MODE=delete`. Runs are logged in `"LapRetentionRuns"` (counts and error messages only) and shown in the Admin page's Lap Telemetry Retention section
- **Collector** (from 1.51.0): deletes a lap's CSV once it's uploaded and has its track positions (as before), at once when the site answers `lapExpired`, and any lap's CSV and `session.json` entry 90 days after completion (`LapWriter.MaxLocalAge`), uploaded or not, then empty session folders; and at startup deletes `.ibt` files over 90 days old in `Documents\iRacing\telemetry` (not while playing a file back). Played-back laps are stamped with when they were driven (the `.ibt`'s start plus `SessionTime`)
- **Not covered**: the Target Lap (the user's choice, kept until replaced or removed), Expert Laps (coaching content) and track bounds and outlines (no user in them)
- **Tests**: `npm run test:lap-retention` (rules at exact UTC boundaries; then the real modules against a local Postgres when `LAP_RETENTION_TEST_DATABASE_URL` is set, see the test's header; it refuses a database that isn't local)

## Race Broadcast

The Race Announcers' two-person spectator broadcast on the Live Racing page and TV Broadcast Mode: it covers the whole field, follows the watched driver more closely, and the Lead (play-by-play) and Color (analyst) announcers work as one team. Deterministic rules decide what's said; the AI only phrases it.

- **Pipeline**: collector live update → `recordLiveUpdate` → `detectRaceEvents` (the driver's own events) and the field-wide `BroadcastTracker` (`src/lib/broadcastTracker.ts`), both into the driver's numbered events → the page sees `eventSeq` go up and posts `/api/live/announcer` (or the TV `/api/tv/announcer`) → `commentate` (`src/lib/announcerCommentary.ts`) → the Commentary Director (`src/lib/broadcastDirector.ts`) picks one event or none (no AI call when none) → a structured request of verified facts → `raceAnnouncerLines` (`src/lib/raceAnnouncer.ts`) → each line checked (`src/lib/broadcastValidation.ts`) → speech at the Director's intensity → the page's `CommentaryQueue` (`src/lib/tvAudio.ts`). A tracker failure is logged and never stops the live data
- **Tracker** (pure): passes seen on track by lap progress (`CarIdxLap` + `CarIdxLapDistPct`, unwrapped across the line), confirmed after 2 s and once per pair in 8 s, same class only; battles between class neighbours by gap (under 0.5 s very close, 1.0 active, 2.0 developing; `TRACKER_CONFIG`), reported again only when the gap moves 0.3 s, with the closing rate per lap; other cars' pit stops with their time on pit road; incidents anywhere but near the driver (those stay `nearbyIncident`), cars in trouble together as one; the grid, the start (`SessionState` parade to racing), the final lap, the winner with the margin and the driver's finish (provisional); storylines (recovery drive, charge through the field, long battle, leader under pressure) with measured facts; every car's clean laps, average, spread, trend, pace rank and places since the start; and prompts for a summary and a statistic every minute or so. The live data has no sector times, tire, fuel, contact or official results, and the prompt says so
- **Director** (pure): priority (P0 critical to P4 background) and intensity (1-5) kept apart; the driver's events weighted by `RELEVANCE_WEIGHTS`, reached as far as the listener's Coverage Focus says, and a rolling coverage count (aim 40/60/75% of discretionary lines about the driver) keeps the field in it; P0 always first. Gates: Broadcast Mode and Commentary Frequency (`MIN_SILENCE_S`, `KIND_INTERVAL_S`), the topic preferences, staleness (each event's `ttlMs`), repetition (same key, or a battle gap within 0.25 s of what was said), and while lines are playing only something more important (`busyPriority`) may replace them (`replaceQueued`). Intensity: the event's base, adjusted for stage, stakes, closeness and the driver; never 5 unless decisive (a last-lap pass for the win, a close or the driver's win); incidents at most 4; continuing situations move a level at a time; capped by Maximum Commentary Intensity, the Color a level under in big moments. Format: Lead, Color, Lead then Color, or Lead/Color/Lead. Every event gets a verdict and reason (`diagnostics`)
- **Generation**: the request names the lines to write (speaker, job, intensity, length); output has `text`, `spoken`, `intensity`, `claims`. A line naming a session driver it wasn't given, writing a number in digits not among the facts, or saying where on the track something happens is dropped, with the lines after it; lines are cut to length and shaped for intensity (no capitals, exclamation marks by level). With Announce driver names off, other drivers are called by car number
- **Speech**: `synthesizeSpeech(..., intensity)`: ElevenLabs gets `voice_settings` (stability, style, speed) moved from each voice's own saved settings by the intensity (`INTENSITY_DELIVERY` in `src/lib/elevenLabs.ts`, so each voice stays itself), or an `[excited]` tag at 4-5 when `ELEVENLABS_MODEL_ID` is an `eleven_v3` model; the OpenAI fallback gets a delivery instruction; Chirp has neither, so the words carry it
- **Playback**: lines come with `priority`, `ttlMs`, `durationMs` and `volume` (Commentary, Lead and Color volumes); the queue plays one at a time, drops lines past their moment and lets `replaceQueued` drop less important waiting lines, never the one playing. The page asks for the next commentary while lines play
- **Preferences** (`src/lib/broadcastSettings.ts`, `src/components/BroadcastSettings.tsx`, `"Users".broadcast_settings`): Broadcast Mode (Off, Quiet, Standard, Full Broadcast, the default), Coverage Focus, Maximum Commentary Intensity, Commentary Frequency, the three volumes, Announce driver names, Statistical analysis, Race strategy discussion, Pre-race introduction and Post-race summary. The Lead/Color checkboxes on the Live Racing page stay per browser. No historical driver statistics: no reliable per-driver history beyond the account's own races
- **Metrics**: `GET /api/admin/broadcast-metrics` (Admins, 404 otherwise; `src/lib/broadcastMetrics.ts`, server memory): requests, answered without AI, suppressed by reason, lines dropped by reason, stale after generation, AI and speech failures, AI, speech and event-to-audio latency, intensity and format counts, the driver's share, ElevenLabs characters, and the latest decisions with their diagnostics. Tokens and cost per call are in the Admin page's AI usage (`raceAnnouncer`)
- **Tests**: `npm run test:broadcast` (simulated races through the tracker and Director, the factual check, preferences and the queue; prints the Director's choices through a whole race)

## Cookie Consent

Optional cookies and browser storage only run with the visitor's consent, given in the cookie banner or Cookie Settings (the footer's Cookie Settings button, `src/components/CookieSettingsButton.tsx`), and described in the Cookie Policy (`/cookies`, `cookiePolicy` in `src/lib/legal.ts`). Audit, design, deployment and open legal questions in `docs/cookie-consent.md`.

- **Inventory**: `src/lib/cookieInventory.ts` lists every cookie and storage item the pages set, with its category; the Cookie Policy's tables and the preference center are made from it. Today the only optional technology is the Activity Log (`visitor_id`, `activitySessionId`, category `analytics`); everything else is strictly necessary. Add a row before adding anything that stores or reads information in the browser, and a new optional category to `OFFERED_CATEGORIES` (`src/lib/cookieConsent.ts`); the source guards in `scripts/cookie-consent.test.mjs` fail otherwise
- **Enforcement**: the root layout reads the `cookie_consent` cookie on the server (`getConsentState`, `src/lib/cookieConsentServer.ts`) and passes it to `CookieConsentProvider`; optional technologies are rendered inside `<ConsentGate category="...">` (`ActivityTracker` is), which renders nothing until granted and unmounts on withdrawal. `/api/activity` also refuses events without a current analytics grant. Nothing optional may load a script, set a cookie or send a request outside a `ConsentGate`

- **Uploads**: each saved lap gets a `clientLapId` in `session.json` and is uploaded right after it's saved; `uploaded`/`uploadError` record the result. At startup, laps from earlier runs that aren't uploaded (and weren't refused) are queued too. Laps saved before session info arrived ("Unknown Track") are kept locally only. Played-back `.ibt` files don't upload unless `--upload` is given. Options: `--set-key`, `--no-upload`, `--upload`, `--site <url>` (this run only, e.g. a local dev server), `--no-positions`
- **Track positions (Lat/Lon/Alt)**: iRacing only writes these to its `.ibt` files, never to live telemetry, so live laps are saved and uploaded with empty `Lat`, `Lon`, `Alt` columns first. When live, the collector turns on iRacing's `.ibt` recording (once per connection, so Alt+L to turn it off sticks), and starts it again when the driver has been in the car 5 s with recording turned on but not recording (getting back in the car in the same iRacing session can leave it like that, and the stint would get no `.ibt` file), once per time in the car. When a stint's recording ends (leaving the car, disconnecting, or at the next startup), `IbtEnricher` reads the finished files in `Documents\iRacing\telemetry`, matches each CSV row by `SessionNum`, `SessionTick` and `SessionTime`, fills in the columns, adds each tire's surface temperatures (`LFtempL`/`M`/`R` to `RRtempL`/`M`/`R`, only in `.ibt` files), replaces the tire carcass temperatures, tire pressures and ride heights with the `.ibt`'s where it has them (live telemetry only updates the carcass temperatures in the pit stall, so a live lap's are one value throughout, and leaves the pressures and ride heights empty), and uploads the lap again. Lap Compare's Tire Temp charts use the surface temperatures, or the carcass ones for laps without them. A lap the `.ibt` doesn't fully cover (e.g. recording started mid-lap) gets `positionMissing` in `session.json`; `hasPosition` marks enriched laps. Laps older than 14 days are left alone. Played-back `.ibt` laps have positions straight away. `--no-positions` turns all of this off for a run

File names are `RacingCoach - Driver - Car - Track - 01.50.486 - S0L005.csv` (`S<sessionNum>L<lap>` ID). A lap's CSV is deleted from the PC once it has uploaded and its track positions are settled (`hasPosition`, `positionMissing`, or older than 14 days), so normally just after the stint, once it's re-uploaded with positions; `csvDeleted` in `session.json` records it, and the lap's entry stays for the window's lap list. Laps that haven't uploaded (refused, Unknown Track, uploads off, played back without `--upload`) keep their CSVs until 90 days after completion, and laps the site refuses as expired lose theirs at once (see Lap Telemetry Retention). The Racing page's lap tabs (`src/lib/lapData.ts`) only accept Garage 61 lap exports
- **Uploads to the website**: the Account page's Telemetry Collector card creates the user's upload key (`/api/collector/key`). Two parts. (1) The plan: whenever the track (or upload key) changes, the collector calls `GET /api/collector/in-car-coach?track=<track>`, which turns the instructions into rules (`inCarCoachPlan`, one model call, cached per instructions, focus areas and language; none without instructions) plus how to deliver lap feedback (`speak`, `show`, `holdInFocusAreas`, `lapFeedback`, `feedbackEveryLaps`), and sends the track's focus areas. The coach talks once per lap: the collector says the callout at once, unless one was already said on this lap, in which case it waits for the next lap to start (only the newest waits). Live laps have no track positions yet, so there's rarely driving line advice. One request at a time; laps that upload meanwhile are sent with the next one. The in-session debrief (`SessionDebrief.cs`) still runs alongside it
- **Coach voice** (`Voice.cs`, `src/lib/coachVoice.ts`, `src/app/api/collector/speech/route.ts`): everything the collector says (In-Car AI Coach callouts and rules, the in-session debrief) is spoken by Google Cloud Text-to-Speech's Chirp 3 HD in the voice the user picked on the Account page (`COACH_VOICES`, default `Charon`; accounts with an older OpenAI voice name get it too), by a native voice of their Preferred Language (`en-US`, `pt-BR`, `de-DE`, or `es-US`/`es-ES` by their Spanish accent; Chirp has no `pt-PT`), or by OpenAI `gpt-4o-mini-tts` told to speak with that accent when `GOOGLE_TTS_API_KEY` isn't set. A Driver box (`src/components/DriverMultiSelect.tsx`, a dropdown of checkboxes) picks whose laps are listed: any number of drivers, or All Drivers. Coaches and Admins (`canSeeAllLaps` in `src/lib/roles.ts`) can see every driver's laps; Users only their own and Coaches' laps, never another User's or an Admin's (`LapViewer` in `src/lib/collectorLaps.ts`, applied in SQL by every lap read: `GET /api/collector/laps?userId=<id,id,...|all>`, which also returns the drivers the user can see, `GET /api/collector/laps/[id]` and `GET /api/collector/rotation`). The routes enforce this, not just the page. A listed lap's `driver` is the name of the RacingCoach account that uploaded it, not the name iRacing reported (`iracingDriver`, `"CollectorLaps".driver`), which is whoever the sim was logged in as, e.g. a friend driving on someone else's iRacing account; sessions are grouped by account. It lists them with `GET /api/collector/laps` and fetches a picked lap's CSV from `GET /api/collector/laps/[id]` (both use the browser sign-in), then analyses it like a dropped CSV. Track names are matched with `sameTrackName` (`src/lib/lapData.ts`), which ignores case, punctuation and a plural "s", because iRacing's names can differ slightly from Track Data's (e.g. "Grand Prix Pit" vs "Grand Prix Pits"). The collector also sends iRacing's track key (`WeekendInfo.TrackName`, e.g. `twinring fullrc`; `TrackKeys` in `RacingCoachApi.cs`) as `key=` on its track requests and `trackKey` with each lap (`"CollectorLaps".track_key`), and the collector routes find the Track Data track with `findTrackByKey` (`src/lib/tracks.ts`), by `"Tracks".track_key` only, never by name, because iRacing can name a layout differently from Track Data and Garage 61 (iRacing's "Mobility Resort Motegi (Full Road Course)" is Track Data's "Mobility Resort Motegi (Grand Prix)"); track lengths are saved by key too (`"Tracks".track_length_feet`). A local record isn't proof of who accepted; the account's records are what count. `scripts/exportLegal.mjs <folder>` writes the documents as HTML from `src/lib/legal.ts` and `versions.iss` from `src/lib/policyVersions.ts`, which the script includes (`/DLegalDir`, default `collector/installer/legal`, git-ignored), so the installer always shows the website's versions. Branding: `collector/installer/branding/` has the Welcome/Finish panel (`wizard-*.png`) and the header badge (`header-*.png`) at every display scale from 100% to 250% (Setup picks the closest), rendered by `generate.mjs` (sharp) from the site's logo (`src/components/Brand.tsx`: the lucide Flag and RACINGCOACH.APP in Barlow Condensed, outlined in `wordmark.svg`/`tagline.svg`, colors in `colors.json`). Pixels of exactly RGB(13, 11, 12) are drawn see-through by Inno Setup 6.7, so `generate.mjs` moves them a step. The wizard follows Windows' light or dark mode (`WizardStyle=modern dynamic`)
- **Local build of the exe**: `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o bin/publish`; then the (unsigned) installer: `node scripts/exportLegal.mjs collector/installer/legal`, then `ISCC /DAppVersion=<version> collector/installer/RacingCoach.Collector.iss` (Inno Setup 6.7.3; the output goes to `collector/installer/Output`)

## Troubleshooting

**npm run dev fails with "command not found"?**
- Ensure Node.js 18+ is installed
- Run `npm install` first
- Check that `.env.local` exists (can be empty initially)

**ESLint errors on import statements?**
- Verify TypeScript path aliases in `tsconfig.json` (e.g., `@/*` → `src/*`)
- Run `npm run lint -- --fix` to auto-fix common issues

**Build succeeds but `npm start` is slow?**
- Normal for first cold start
- Production bundle includes optimizations
- Subsequent requests are faster
